# 完赛判定切换与从零重新训练

## 两种模式

- `original`（默认）：沿用安装的 Gymnasium 完赛判定，旧检查点缺少模式字段时也按 original 处理。
- `lap95`：访问全部路块时完赛；或者车辆离开起点路块后，再次进入起点路块，覆盖率严格大于 95%，且车身速度在赛道起点正向切线上的投影为正时完赛。起点接触由任意车轮接触 tile 0 定义；正向切线取起点前后相邻中心点之差。这个模式不再要求起点路块此前没有访问过。

新模式每个物理帧检查，成功时设置 terminated=True、lap_finished=True，并立即停止本次动作重复。原有出界失败仍保留为失败；时间上限仍是 1000 原始帧，奖励、图像、动作空间、动作重复次数不变，不增加完赛奖励。若恰在时限帧完赛，terminated 和 truncated 可以同时为 True，训练按真正终止不 bootstrap。

仅覆盖 95% 而没有回到起点，不算完赛；逆向重返起点不触发 95% 规则；原有访问 100% 路块的完赛规则不要求回到起点或方向。该模式是项目定义的修订协议，不应与原环境成绩无标注混合，也不保证解决离路或逆行问题。

所有修改均在项目源码中，没有修改 Anaconda 的 site-packages。

## 2. 从零训练 PPO，使用新完赛规则

```bat
python -m racing.train --algo ppo --seed 0 --steps 1000000 --device cuda --num-envs 4 --rollout 128 --batch-size 128 --actor-lr 1e-4 --critic-lr 3e-4 --ppo-epochs 10 --completion-mode lap95 --eval-every 100000 --eval-episodes 20 --out runs_lap95_lr1e4
```

这条命令不加载旧模型，从零开始累计 100 万决策；不使用此前失败的 KL 提前停止配置。其余核心优化参数沿用此前 actor_lr=1e-4 的 PPO。每约 10 万决策以及训练结束时，评估固定 20 条验证赛道（1000000–1000019）。预计约 10–12 小时，按设备负载与评估耗时变化。

输出目录：`runs_lap95_lr1e4/ppo_s0/`。其中 best.pt 是验证最佳模型，last.pt 是预算结束模型；config.json、两个检查点的 env_config 都记录 completion_mode。脚本拒绝覆盖已有目录；重跑时换 --out，例如 runs_lap95_lr1e4_v2，并同步替换后续命令里的路径。

不要添加 --resume 或 --branch-from 来加载原模式模型。代码会拒绝在严格续训中切换环境判定，避免把不同训练协议混为一条学习曲线。

## 3. 先生成验证视频，查看驾驶能力

```bat
python -m racing.evaluate --checkpoint runs_lap95_lr1e4\ppo_s0\best.pt --device cuda --episodes 5 --seed-start 1000000 --videos 5 --out runs_lap95_lr1e4\ppo_s0\validation_video_best
python -m racing.evaluate --checkpoint runs_lap95_lr1e4\ppo_s0\last.pt --device cuda --episodes 5 --seed-start 1000000 --videos 5 --out runs_lap95_lr1e4\ppo_s0\validation_video_last
```

评估默认读取检查点的判定模式，因此自动使用 lap95。两组视频均在各输出目录的 videos 子目录中。分别录制 best 和 last，避免只看保留下来的早期最佳模型而误判最终训练效果。视频回报是 5 条验证赛道结果，不要冒充独立测试成绩。

## 4. 方案固定后，评估 50 条独立赛道

```bat
python -m racing.evaluate --checkpoint runs_lap95_lr1e4\ppo_s0\last.pt --device cuda --episodes 50 --seed-start 3000000 --videos 5 --out runs_lap95_lr1e4\ppo_s0\test
python -m racing.evaluate --checkpoint runs_lap95_lr1e4\ppo_s0\best.pt --device cuda --episodes 50 --seed-start 3000000 --videos 5 --out runs_lap95_lr1e4\ppo_s0\test_best
```

两组使用相同的赛道。summary.json 记录实际 completion_mode、checkpoint_completion_mode 与是否覆盖协议；episodes.csv 记录逐赛道成绩；videos 保存前 5 条赛道的完整视频。如果后来用这些测试结果调参，最终需要另选未用于调参的测试赛道。

## 5. 生成可视化报告

```bat
python -m racing.report --root runs_lap95_lr1e4
python -m racing.report --root runs_lap95_lr1e4 --selection test_best
start "" "runs_lap95_lr1e4\report\index.html"
start "" "runs_lap95_lr1e4\report_test_best\index.html"
```

第一个报告比较固定预算最终模型，第二个报告展示验证选择的最佳模型。报告拒绝将 original 和 lap95 混合汇总。只有 seed=0 时不具备跨训练随机种子的统计结论。

## 原模式与其他算法如何运行

从零复跑原判定，只需使用 original 并换一个输出根目录：

```bat
python -m racing.train --algo ppo --seed 0 --steps 1000000 --device cuda --num-envs 4 --rollout 128 --batch-size 128 --actor-lr 1e-4 --critic-lr 3e-4 --ppo-epochs 10 --completion-mode original --eval-every 100000 --eval-episodes 20 --out runs_original_control
```

这条是可选的严格协议对照，不需要现在同时运行。此前旧实验包含多次重启续训，适合作历史参考，不是除环境外完全一致的连续训练对照。比较原/新环境时完成率定义不同，应明确标注；最好将固定模型分别在两个模式下评估，以区分判定变化和重新训练的影响。

其他算法同样支持 --completion-mode lap95。套件也可传入该参数，例如小规模自检：

```bat
python -m racing.suite --preset smoke --algos ppo --device cuda --completion-mode lap95 --out runs_lap95_suite_check
```

注意 suite 使用自己的预设超参数，上述 smoke 仅用于检查流程，不替代第 2 步训练方案。

评估时可以显式覆盖模式，例如旧检查点的新规则诊断：

```bat
python -m racing.evaluate --checkpoint runs_tuning_lr1e4_1000k\ppo_s0\best.pt --device cuda --completion-mode lap95 --episodes 20 --seed-start 1000000 --videos 5 --out runs_lap95_old_model_diagnostic
```

这是旧模型在新协议下的诊断，不是重新训练的结果。输出明确标记 protocol_override=true；默认不传 --completion-mode 时始终继承检查点协议。

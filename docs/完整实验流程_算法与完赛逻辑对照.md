# CarRacing 完整实验流程：算法与完赛逻辑对照

本文从 Conda 虚拟环境已经安装完成开始，说明如何选择完赛规则和强化学习算法，运行对照实验，并生成数据表、学习曲线、驾驶视频和赛道轨迹图。所有示例在 Windows Anaconda Prompt 中执行，项目目录为 `D:\Desktop\RL_project`。

**GRPO-C 版本更新：**当前为 v2，修复了状态基线和参考分布，采用明确记录的低刹车初始化。旧 v1 检查点仍可评估，但不能接入 v2 续训。先按 [GRPO-C 停滞修复与重跑](GRPO-C停滞修复与重跑.md) 做短实验。suite 省略 `--actor-lr` 时，GRPO-C 使用 `1e-4`，其他算法保持 `3e-4`；也可显式传入该参数统一指定。

## 1. 激活环境并确认 GPU

每次开始实验先运行：

```bat
conda activate rl_carracing
cd /d D:\Desktop\RL_project
python -c "import torch; print('PyTorch:',torch.__version__); print('CUDA:',torch.cuda.is_available()); print(torch.cuda.get_device_name(0) if torch.cuda.is_available() else 'CPU only')"
```

本机安装的 PyTorch 识别 NVIDIA RTX 3060 Laptop 为 `cuda:0`，因此命令使用 `--device cuda`。Windows 任务管理器的 GPU 编号和 CUDA 设备编号可能不同。

建议先用全新目录做一次小规模流程自检。自检不会覆盖任何已有实验：

```bat
python -m racing.suite --preset smoke --algos ppo grpo-c --completion-mode lap95 --device cuda --out runs_workflow_smoke
```

Smoke 只验证训练、评估、检查点、视频和报告流程，不用于比较算法。它完成后会在 `runs_workflow_smoke\smoke\report\index.html` 生成汇总页。

## 2. 选择完赛判断逻辑

训练命令通过 `--completion-mode` 选择规则；可选值如下。

| 参数 | 完赛条件 | 适用问题 |
|---|---|---|
| `original` | Gymnasium CarRacing 原始完赛规则 | 保持环境原始定义；作为基准协议 |
| `lap95` | 覆盖全部路块，或离开起点后正向重返起点且覆盖率严格超过 95% | 检验此前“覆盖率很高但没有触发原生完赛”的情况 |

`lap95` 在每个物理帧检查起点重返和行驶方向；保留原有出界失败和 1000 原始帧时限。单纯覆盖超过 95% 但没正向回到起点，不算完赛。两种规则改变了任务的终止条件，完赛率必须在各自规则下单独解释。

**比较完赛规则时，要分别从头训练并使用不同输出目录。**不要把 `original` 检查点续训成 `lap95`，也不要把两种模式的分数放进同一份汇总报告。评估命令默认沿用检查点记录的规则；手动传 `--completion-mode` 会形成规则覆盖诊断，不等于该规则下重新训练的结果。

## 3. 选择算法

当前训练入口和 suite 支持以下算法，可在命令行组合选择：

| `--algo` / `--algos` 名称 | 方法 | 在本项目中的作用 |
|---|---|---|
| `a2c` | 同步优势 Actor-Critic，使用 GAE | 基线；一次更新，流程简单 |
| `ppo` | PPO-Clip | 常用连续控制策略梯度基线，支持多轮小批量更新 |
| `vpg50` | VPG-repeat，价值网络重复更新 50 次 | 检查增加 critic 更新能否改善价值估计和策略表现 |
| `grpo` | 同赛道多完整轨迹的组相对策略优化适配 | 无 critic；每轮保留完整轨迹，决策预算可能略超目标 |
| `grpo-c` | 论文框架的连续控制适配实现 | 独立高斯策略、轨迹/状态聚类、组自适应裁剪及连续控制正则；无 critic |

可只比较一种算法，也可以给 `--algos` 传入多个名称。例如：

```bat
python -m racing.suite --preset pilot --algos a2c ppo grpo grpo-c --completion-mode lap95 --device cuda --out runs_lap95_pilot
```

建议先用 `pilot` 观察每个方法的学习趋势和运行时间。要完整覆盖五种算法，将命令改为 `--algos a2c ppo vpg50 grpo grpo-c`。GRPO 和 GRPO-C 会按完整轨迹/策略组采样，可能比 A2C、PPO 慢，而且实际决策数可能略超预算；报告会标出实际预算。

## 4. 先跑 pilot，再跑正式矩阵

### 4.1 单模式算法筛选

下面示范在 `lap95` 下对五种算法做 10 万决策、一个训练种子的 pilot：

```bat
python -m racing.suite --preset pilot --algos a2c ppo vpg50 grpo grpo-c --completion-mode lap95 --device cuda --out runs_lap95_pilot
```

若要检查原始规则，使用另一个输出目录从头运行：

```bat
python -m racing.suite --preset pilot --algos a2c ppo vpg50 grpo grpo-c --completion-mode original --device cuda --out runs_original_pilot
```

Pilot 的用途是筛查训练是否有上升趋势、完赛判定是否符合预期、视频/报告是否正常，以及时间是否可接受。默认只有 seed 0；suite 会用 5 条赛道做周期验证、10 条赛道测试，并为测试视频录制代表赛道。Pilot 不能据此声称算法排名稳定或有统计显著差异。

### 4.2 正式多随机种子对照

确认硬件时间和 pilot 结果后，使用 `main`。该预设默认 100 万决策、训练种子 0/1/2，并对两个完赛模式分别运行：

```bat
python -m racing.suite --preset main --algos a2c ppo vpg50 grpo grpo-c --completion-mode original --device cuda --out runs_original_main
python -m racing.suite --preset main --algos a2c ppo vpg50 grpo grpo-c --completion-mode lap95 --device cuda --out runs_lap95_main
```

完整矩阵包含 2 种完赛模式 × 5 种算法 × 3 个训练种子，共 30 次训练，资源开销较大。可以先根据研究问题缩小 `--algos`，例如只选 `ppo grpo grpo-c`；也可以先使用 `--steps 100000` 做预算统一的短 pilot。需要更可靠的训练种子统计时，可通过 `--seeds 0 1 2 3 4` 扩展到五个种子，时间也会相应增加。

每种完赛模式必须保留独立的 `--out` 根目录。训练目录已存在时，脚本不会覆盖；重复实验请使用新目录名。`--device cuda` 是默认建议；没有可用 CUDA 时可显式改为 `--device cpu`，但训练会更慢。

### 4.3 预算与停止点

项目的 A2C/PPO/VPG 短测约为每秒 47–70 个决策，但这不是长训练保证。GRPO-C 两策略短自检曾测得约 8.4 决策/秒；四策略、正式参数和验证负载会改变吞吐。先用 pilot 的 `finished.json` 读取实际训练时间和决策数，再估算正式实验。配置与成本背景见 [配置与时间成本](配置与时间成本.md)。

## 5. 读取训练结果并生成报告

`suite` 会依次训练每个指定方法，评估 `last.pt` 和 `best.pt`，最后自动生成 `last` 测试汇总。以 lap95 pilot 为例：

```bat
python -m racing.report --root runs_lap95_pilot\pilot --allow-unequal-budgets
python -m racing.report --root runs_lap95_pilot\pilot --selection test_best --allow-unequal-budgets
start "" "runs_lap95_pilot\pilot\report\index.html"
start "" "runs_lap95_pilot\pilot\report_test_best\index.html"
```

`--allow-unequal-budgets` 用于 GRPO/GRPO-C 完整轨迹采样导致的实际决策数差异；它会在报告中明确标出预算不完全相等。两种 completion mode 要在不同 root 下分别生成报告。

主要产物：

| 文件或目录 | 内容 |
|---|---|
| `report/index.html` | 汇总表、图表和测试视频的离线报告页 |
| `report/comparison.csv` | 各算法均值、训练种子数、测试回报、完赛率、覆盖率、耗时和吞吐 |
| `report/per_run.csv` | 每个训练种子的指标、验证 AUC 和实际检查点决策数 |
| `report/paired_differences.csv` | 相同训练种子下算法间的配对差异 |
| `report/all_test_episodes.csv` | 每个测试赛道的逐局原始数据 |
| `report/learning_curve.png` | 验证回报随策略决策数变化的折线图 |
| `report/frame_curve.png`、`report/time_curve.png` | 验证回报随原始物理帧数、训练时间变化的折线图 |
| `report/diagnostics.png` | value MSE、近似 KL、解释方差；GRPO/GRPO-C 的 critic 指标显示为不适用 |
| `report/test_seeds.png` | 各独立训练种子的测试回报散点图 |
| `pilot/<algo>_s<seed>/test/videos/` | last 检查点的固定测试赛道视频 |
| `pilot/<algo>_s<seed>/test_best/videos/` | 验证表现最佳检查点的固定测试赛道视频 |

`best.pt` 是根据验证集选择的模型，`last.pt` 是预算结束模型。主要结论应同时查看最后模型和最佳模型，避免只报告验证挑选后的最好成绩。三个训练种子可以显示初步变异，但统计区间仍不稳定；测试赛道数增加不能替代独立训练种子。

## 6. 生成视频与同赛道并排比较

Suite 会在测试结果中为代表性赛道录制视频。pilot 默认测试赛道种子从 2,000,000 开始，可把多个算法同一赛道的视频合成为并排对照：

```bat
python -m racing.video_grid --inputs runs_lap95_pilot\pilot\ppo_s0\test\videos\track_2000000.mp4 runs_lap95_pilot\pilot\grpo_s0\test\videos\track_2000000.mp4 runs_lap95_pilot\pilot\grpo-c_s0\test\videos\track_2000000.mp4 --labels PPO GRPO GRPO-C --out runs_lap95_pilot\pilot\same_track_2000000.mp4
```

`--inputs` 中的每条视频必须来自同一个完赛模式、相同赛道种子和相同评估类型（都选 `test` 或都选 `test_best`）。标签数量必须和输入数量相同。输出视频保持原始 50 FPS；完整原始帧录制可能耗时，pilot 阶段建议只录少量代表性赛道。

如果只想评估某个已有模型并另录验证视频，可执行：

```bat
python -m racing.evaluate --checkpoint runs_lap95_pilot\pilot\ppo_s0\best.pt --device cuda --episodes 1 --seed-start 1000000 --videos 1 --out runs_lap95_pilot\pilot\ppo_s0\validation_video_best
```

这会在 `validation_video_best\videos\track_1000000.mp4` 录制指定赛道。验证赛道用于模型选择，不要把它当作独立测试赛道。

## 7. 生成驾驶轨迹图和逐帧遥测

驾驶诊断工具会读取一个已有运行目录中的 `best.pt` 和对应视频，并生成观测帧拼图、覆盖率/速度/油门/刹车/转向曲线、车辆的 x-y 赛道轨迹图，以及逐帧 CSV。先按上一节为同一验证赛道录制视频，再运行：

```bat
python scripts/diagnose_driving.py --run runs_lap95_pilot\pilot\ppo_s0 --device cuda --seed-start 1000000 --episodes 1 --video-subdir validation_video_best --out-name driving_diagnosis
```

产物在 `runs_lap95_pilot\pilot\ppo_s0\driving_diagnosis\`：

- `frames_1000000.jpg`：从视频抽取的驾驶画面拼图。
- `trace_1000000.png`：覆盖率、速度、油门/刹车、方向和轮胎接地比例随时间变化。
- `path_1000000.png`：车辆 x-y 位置与赛道中心线的轨迹图。
- `telemetry_1000000.csv`：逐物理帧车辆位置、动作、速度、路块覆盖和回报。
- `summary.json`：诊断汇总。

若要对比别的算法，把 `--run` 改成对应算法的同种子目录，并确保它有同样种子的 `validation_video_best` 视频。该脚本的延长时限片段是驾驶诊断用途；正式结果仍以环境原始 1000 帧上限和标准评估 CSV 为准。

## 8. 单独运行一个算法

需要修改单算法参数时可直接调用 `racing.train`。例如，从零训练 10 万决策的 lap95 PPO：

```bat
python -m racing.train --algo ppo --seed 0 --steps 100000 --device cuda --num-envs 4 --rollout 128 --batch-size 128 --actor-lr 1e-4 --completion-mode lap95 --eval-every 25000 --eval-episodes 5 --out runs_manual_lap95
```

将 `--algo ppo` 改为 `a2c`、`vpg50`、`grpo` 或 `grpo-c` 可切换算法。五种实现的特定参数可查询：

```bat
python -m racing.train --help
```

单算法训练完成后，按第 5–7 节对该检查点运行 `racing.evaluate`、`racing.report`（报告根目录是 `--out` 指向的目录）和 `scripts/diagnose_driving.py`。完整方法说明见 [GRPO 运行指南](GRPO运行指南.md)、[GRPO-C 运行指南](GRPO-C运行指南.md)和[完赛判定切换说明](完赛判定切换与重新训练.md)。

## 9. 结果解释与归档

1. 先确认每个 `config.json` 中的 `algo`、`completion_mode`、seed 和预算，报告不能混合两种完赛规则。
2. 对比算法时固定规则、训练步数、测试赛道集合和评估方式；GRPO 家族以 `finished.json` 的实际 `steps` 为准。
3. 同时报告回报、完赛率、覆盖率、训练耗时和学习曲线；不要只用一次短跑或单个最佳视频下结论。
4. 保留报告 HTML、CSV 原始数据、配置/软件版本、检查点和视频。正式对照至少使用 3 个独立训练种子，资源允许时建议 5 个。

完成后退出环境：

```bat
conda deactivate
```
